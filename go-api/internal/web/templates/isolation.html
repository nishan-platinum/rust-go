Multi-tenant isolation test

Calls the tenant API over real HTTP, hitting all {{len .Data.Tenants}} tenant databases at the same time, and checks that no data, DB session or token crosses tenants.

  1. Load: concurrent reads and writes across every tenant. Each response is checked against the marker stored inside the tenant's own database, the DB session state left on pooled connections, and the owner of every row returned.
  2. Hot pool swap: halfway through, one tenant's config version is bumped while requests are in flight. The engine must swap pools without failing any request.
  3. Tokens: a cross-tenant token, a tampered token, alg=none, the wrong key, an expired token, the wrong audience and a revoked token must all be rejected.
  4. Sessions: missing, forged or expired admin sessions, missing or wrong CSRF tokens, and logout revocation.
